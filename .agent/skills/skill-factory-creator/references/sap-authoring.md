# SaP Authoring (Three Blocks + Contract)

Rule of the paper (docs section 1): bundle (templates + skeleton + contracts) 30/134; template-only 25; length-matched prose 18; raw prose 16; contract-only 13. Order matters: concrete syntax first.

## Block 1: Action Templates (read first)

- Fenced `bash` block, first line is the tag comment: `# [κ: <contract-id>] parent=<skill> required_inputs=[...]`.
- 2 to 8 real commands. Placeholders use `{snake_case}` matching `input_schema.required` keys.
- Each command ends `| bin/rtk`. AST scripts: `/usr/bin/python3 .agent/skills/skill-code-map/scripts/<tool>.py ...`.
- Prefer read-only discovery commands (`ls`, `grep -n`, `--help`) over mutating ones. Mutations need a `confirm` precondition.

## Block 2: Procedural Skeleton

```text
PROCEDURE run_<skill_name_with_underscores>_workflow(<required inputs>):
  1. PRE-CHECK: <preconditions joined by ;>
  2. result <- invoke(<contract-id>, {<input>: "<input>", ...})
  3. POST-CHECK: <postconditions joined by ;>
  4. RETURN {Location, Problem, Fix, outputs: [<output keys>]}
```

Keep `invoke(<id>` literal: `verify_rc_bundle` regex-matches it.

## Block 3: Inlined Child Contracts

One bullet group per contract: `trigger`, `inputs` (required/optional), `outputs`, `preconditions`, `postconditions`, `side_effects`. Abstract guarantees only; no commands here.

## Contract YAML (`.agent/contracts/<id>.yaml`)

```yaml
id: kebab-case-id
trigger: one line; shared procedural intersection of parents
input_schema:
  required: {slot: type}
  optional: {slot: type}
output_schema: {key: type}
preconditions: [..]
postconditions: [..]
resources: [relative paths used]
side_effects: {filesystem: "none|writes X", network: "none|read-only X"}
source_parents: [skill-a]
action_templates: ["cmd {slot} | bin/rtk"]
```

Validate against `.agent/adapters/schemas/contract.schema.json`. `bindings` and `verifier_stats` are generated by the compiler; do not hand-write them.

## Authoring workflow

1. Write domain body of `SKILL.md` first (rules, tables, runbook index).
2. Draft contract in `scripts/sap/compile_corpus.py` `CONTRACTS_CATALOG` (the generator of record), not as a standalone hand-made YAML.
3. Run the compiler only with USER approval: it rewrites all parents and agents. Review `git diff --stat`; unexpected files = stop.
4. Verifier must report tier `auto_promote`. `review` or `reject` = narrow the trigger or add real tokens to the parent text; do not lower thresholds.

## Lessons to apply (docs section 2)

| Lesson | Apply |
| :--- | :--- |
| Over-wide clustering | Trigger from shared tokens only |
| Retrieval pollution | Children in contracts/, never skills/ |
| invoke() vs shell | Keep guard header |
| Rewrite cleanup | `/usr/bin/python3` and a trailing `bin/rtk` pipe everywhere |
| Deterministic risk | Declare side effects + confirm precondition |
